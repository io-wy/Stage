# 戏台观测方式

跑一次 `uv run python run.py "你的任务"` 后，你可以从 **3 层 7 面** 观测戏台的全部行为。

---

## 第一层：终端实时流（stderr）

跑任务时终端实时输出，不需要等结束就能看到进展。

### 1. 事件流

每条事件按 `[时间] event.type — 详情` 格式实时刷新：

```
[14:16:16] tasks.imported        — Imported 1 task(s) from graph
[14:16:16] project.started       — Project proj-5122e751 started
[14:16:19] [director] sdk.llm.succeeded — latency=3016ms, tokens=6348+56
[14:16:19] [director] sdk.tool.called   — tool=show_state
[14:16:25] [director] sdk.llm.succeeded — latency=6206ms, tokens=6429+113
[14:16:35] [director] sdk.tool.called   — tool=spawn_agent
[14:16:35] [coder-t1] agent.registered  — Registered coder
[14:16:35] task.running          task=t1 — status=running
[14:16:48] [coder-t1] sdk.tool.called   — tool=write_file
[14:16:48] [coder-t1] sdk.tool.succeeded — tool=write_file
[14:16:52] [coder-t1] sdk.tool.succeeded — tool=bash
[14:16:54] task.completed        task=t1 — status=completed
[14:17:07] orchestrator.finalized — all done
```

事件类型前缀约定：

| 前缀               | 含义                          |
| ------------------ | ----------------------------- |
| `task.*`         | 任务状态变更                  |
| `agent.*`        | agent 生命周期                |
| `sdk.llm.*`      | LLM 调用（含延迟和 token 数） |
| `sdk.tool.*`     | 工具调用                      |
| `budget.*`       | 预算消费                      |
| `orchestrator.*` | 编排器自身事件                |
| `mail.*`         | 消息投递                      |
| `resident.*`     | 常驻 agent 状态               |
| `trace.*`        | 分布式追踪                    |

### 2. Agent 追踪（Trace）

每个 agent 结束（成功或失败）时输出追踪摘要：

```
  --- coder (coder-t1) trace ---
  turns: 1 user / 4 assistant
  tools: glob → read_file → write_file → read_file → bash → complete_task
  output: Created the root-level executable shell script `hello.sh`...
```

失败时显示错误信息：

```
  --- coder (coder-t1) trace ---
  turns: 0 user / 0 assistant
  ERROR: HTTP 429: rate limit exceeded
```

### 3. 事件时间线（EVENT TIMELINE）

任务结束时打印按时间排序的完整事件表：

```
--- EVENT TIMELINE ---
  +   0.0s  tasks.imported        — Imported 1 task(s) from graph
  +   3.1s  sdk.llm.succeeded     agent=director  — latency=3016ms, tokens=6348+56
  +  18.8s  agent.registered      agent=coder-t1  — Registered coder
  +  38.5s  task.completed        task=t1  — status=completed
  +  50.8s  orchestrator.finalized  — all done
```

精确到 ±0.1s，可追踪每一步耗时。

## 第二层：磁盘持久化

每次运行自动在 `.claude/persist/session-<id>/` 下保存完整数据：

```
.claude/persist/session-cd1dc552/
├── events.jsonl          ← 全部事件，追加式 JSONL，可回放
├── snapshots/             ← 每 20 个事件自动快照（完整 StateBoard）
│   ├── stateboard-20.meta.json
│   ├── stateboard-20.json
│   ├── stateboard-40.json
│   └── ...
└── residents/             ← 每个 agent 的完整对话 transcript
    └── coder-t1.json
```

### 常用查询

```bash
# 看所有任务状态变更
grep 'task\.' .claude/persist/session-xxx/events.jsonl

# 看 agent 失败
grep 'agent.failed' .claude/persist/session-xxx/events.jsonl

# 看消息投递
grep 'mail\.' .claude/persist/session-xxx/events.jsonl

# 看 LLM 延迟分布
grep 'llm.succeeded' .claude/persist/session-xxx/events.jsonl | grep -o 'latency=[0-9]*'

# 统计事件类型分布
grep -o '"type":"[^"]*"' .claude/persist/session-xxx/events.jsonl | sort | uniq -c | sort -rn
```

## 运行时 Flag

```bash
# 开启 Prometheus 风格指标
uv run python run.py "任务" --metrics

# 开启审计日志
uv run python run.py "任务" --audit

# 开启 7 维度 eval 报告（含 Agent-as-Judge）
uv run python run.py "任务" --eval

# 跳过 Judge（纯客观指标，更快）
uv run python run.py "任务" --eval --skip-judge

# 显示 Judge 推理详情
uv run python run.py "任务" --eval -v
```

## Agent 间通信

戏台内 agent 通过 Mailbox v2 通信，每条消息都会产生可观测事件。

### 通信事件类型

| 事件                        | 含义                                                              |
| --------------------------- | ----------------------------------------------------------------- |
| `message.sent`            | `send_message` 工具被调用，含 `from`/`to`/`content`       |
| `mail.routed`             | 消息被路由表解析后投递到目标 mailbox，含 `topology`/`targets` |
| `mail.policy_blocked`     | 消息被 ChannelPolicy 拦截                                         |
| `collab.process_messages` | 协作循环开始处理各 task 的 mailbox 信号                           |
| `mail.dlq_replayed`       | 死信队列中的消息被 Director 手动重播                              |

### 实际通信事件示例

来自真实协作模式 session：

```
[   5] collab.process_messages — threads=[] tasks=[('t1','pending'), ('t2','pending'), ...]
[  15] collab.process_messages — threads=['task-t1'] tasks=[('t1','running'), ...]
[ 120] message.sent     agent=coder-t1  — to=reviewer-t1: TASK_REVIEW_READY[t1]: tests passed=2
[ 125] mail.routed      agent=coder-t1  — topology=p2p targets=['reviewer-t1']
[ 130] collab.process_messages — threads=['task-t1'] tasks=[('t1','review'), ...]
```

### 查询通信记录

```bash
# 看所有消息收发
grep 'message.sent\|mail.routed' .claude/persist/session-xxx/events.jsonl

# 看协作信号处理
grep 'collab.process_messages' .claude/persist/session-xxx/events.jsonl

# 看被拦截的消息
grep 'mail.policy_blocked' .claude/persist/session-xxx/events.jsonl

# 用 Python 提取通信轨迹
python3 -c "
import json
targets = {'message.sent', 'mail.routed', 'collab.process_messages', 'mail.policy_blocked'}
for line in open('.claude/persist/session-xxx/events.jsonl'):
    e = json.loads(line)
    if e.get('type') in targets:
        print(json.dumps(e, ensure_ascii=False))
"
```

> **注意**：单 agent 任务（如 `"Write hello.sh"`）没有通信。需要多 agent 协作任务（`--collaborative-mode on`）才会产生通信事件。

### 启用 Matrix 后端通信

戏台支持把 agent 间消息镜像到 Matrix 房间。启用需要三个环境变量：

```bash
export MATRIX_HOMESERVER="https://matrix.org"
export MATRIX_USER_ID="@yourname:matrix.org"
export MATRIX_ACCESS_TOKEN="syt_..."
```

Access Token 获取方式：

- **Element 网页版**：登录 [app.element.io](https://app.element.io) → Settings → Help & About → Advanced → Access Token
- **curl 登录私有 Synapse**：

```bash
curl -X POST https://matrix.example.com/_matrix/client/r0/login \
  -H "Content-Type: application/json" \
  -d '{"type":"m.login.password","user":"yourname","password":"yourpassword"}'
```

启动协作任务时如果 Matrix 可用，日志会打印：

```
[Orchestrator] Matrix transport enabled: @yourname:matrix.org @ https://matrix.org
```

如果连接失败会自动降级：

```
[Orchestrator] Matrix transport init failed: ...; continuing without Matrix.
```

> 当前实现所有 agent 共用同一个 Matrix 身份收发消息，room 按 `dm-{from_agent}-{to_agent}` 命名。

## 三层次关系

```
终端实时流（stderr）  ──→  边跑边看，即时感知
磁盘持久化（JSONL）   ──→  事后回溯，数据不丢
最终报告（stdout）    ──→  结论汇总，一目了然
```

三个层次互不依赖。任意一个断了（终端关了、磁盘满了、报告解析失败）都不影响另外两个。
